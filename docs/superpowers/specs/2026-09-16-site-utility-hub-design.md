# サイト実利ハブ再構成 設計

## 目的

公式サイトを、Discord サーバーの紹介を読む場所から、いど端で現在使える活動・プロジェクト・チャンネルへ進むための入口へ作り変える。

新規参加者向けの説明は必要最小限にし、既存メンバーにも継続して使う理由がある構成にする。

## 現状の問題

- Home の主な内容がチャンネル一覧だけで、活動やプロジェクトへ進めない
- チャンネル一覧に音声チャンネルとステージチャンネルが含まれていない
- LayerNote、ido-bata-server-bot、いど端 底力 タイムの説明と導線がない
- FAQ、Rules、News に準備中の文章や空状態が残っている
- Discord CTA のスタイルが場所ごとに異なり、ブランドカラーと文字色が統一されていない
- サーバーの理念を説明する文章が、サイトの中心機能より目立っている

## 情報設計

### Home

Home はサイト全体の実利ハブとする。上から次の順に配置する。

1. 短いサーバー説明と主要導線
   - Discord に参加
   - チャンネルを探す
   - ルールを確認
2. 現在使える活動・プロジェクト
   - いど端 底力 タイム
   - LayerNote
   - ido-bata-server-bot
3. チャンネルの概要
   - 話題、共有、雑、PDCA、作業などの用途
   - テキスト、フォーラム、音声、ステージを区別して表示
4. 更新情報
   - 実在する更新のみ表示
5. 初めての方向け導線
   - `/welcome` への控えめなリンク

紹介文は一段落に抑える。活動やプロジェクトのカードは、名称だけでなく「何に使えるか」と次の行動を示す。

### 活動ページ

`/activities/idobata-time` を追加する。

掲載内容:

- 毎日 21:00〜22:40 に開催
- 15分作業、5分休憩、30分作業、5分休憩、45分作業の流れ
- `いど底-ステージ` を各自の作業時間として利用できること
- 反応や発言は不要であること
- ido-bata-server-bot が音声とテキストで区切りを案内すること
- Discord 参加導線と server bot ページへのリンク

### プロジェクトページ

#### `/projects/layer-note`

LayerNote を After Effects 用 CEP 拡張として説明する。

- レイヤーのメモ管理
- プロパティとエクスプレッションの閲覧・編集
- 検索、整形、検証
- GitHub Releases からのインストール
- GitHub リポジトリ、ユーザーガイド、開発参加へのリンク

実装済みの機能と、開発予定を混同しない。

#### `/projects/server-bot`

Discord サーバー運営用 bot として説明する。

- 底力タイムの進行
- 音声・ステージ接続
- リアクションロール
- サーバーイベント、リアクション、メッセージ、ボイス状態を扱う基盤
- GitHub リポジトリへのリンク

ユーザーが現在利用できる機能と、リポジトリ上で準備中の機能を区別する。README の古い Current scope より、動作中の Discord イベントと現行コードを優先する。

### チャンネル一覧

`Channel` に次の種別を追加する。

- `text`
- `announcement`
- `forum`
- `voice`
- `stage`

公開中の現行構成を掲載し、少なくとも以下を追加する。

- `いど底-ステージ`
- `作業 (修羅場)`
- `作業 (雑)`
- `作業（無言）`
- いど端LT会の `ボイスチャンネル`

Legacy カテゴリは現行機能の案内から除外する。各項目には種別ラベルまたはアイコンを表示する。

### FAQ・Rules・News

#### FAQ

確認済みの事実に基づき、次を掲載する。

- いど端とは何か
- 何に使えるか
- 参加後にどこを見ればよいか
- 制作途中の投稿や質問をしてよいか
- 音声チャンネルや底力タイムへの参加方法
- プロジェクトへの参加方法

#### Rules

`docs/code-of-conduct.md` を正本として、Web で参照しやすい要約を掲載する。

- 実利重視
- 情報共有
- 自由参加・自由退出
- 推奨されるふるまい
- 禁止行為
- 問題発生時の連絡先

Web 側で独自ルールを追加しない。

#### News

空の告知一覧を表示しない。現時点で確認できる活動開始・プロジェクト更新を掲載する。日付と出典が確定できない項目は News に入れず、Home の恒常的な機能カードとして扱う。

## Discord CTA

Discord 専用コンポーネントを追加し、すべての参加導線で使用する。

- 通常背景: `#5865F2`
- hover 背景: `#4752C4`
- 文字・アイコン: 常に `#FFFFFF`
- focus-visible: 既存のアクセシブルなフォーカスリングを維持
- light / dark theme で同じブランド表現を使う
- Header、Home、Welcome、Footer、FAQ、404で共通化

環境変数未設定時は参加ボタンを表示しない。利用できないボタン風プレースホルダーは表示しない。

## データ管理

静的エクスポートの安定性を保つため、Discord API と GitHub API を実行時・ビルド時には呼ばない。確認済みの内容を型付きデータとしてリポジトリ内に保持する。

- チャンネル: `src/content/channels.ts`
- 活動: `src/content/activities.ts`
- プロジェクト: `src/content/projects.ts`
- FAQ: `src/content/faq.ts`
- Rules: `src/content/rules.ts`
- News: `src/content/news.ts`

Discord と各 GitHub リポジトリを正本とし、サイト側は読者向けの案内に必要な範囲だけを保持する。

## レイアウト

既存の container、grid、stack、section recipe を使う。Home の面積と順序で重要度を表し、紹介文より機能カードを大きく扱う。

- デスクトップ: 活動・プロジェクトを3列、チャンネル用途を複数列で表示
- モバイル: 重要度順に1列へ並べる
- カード全体をリンクにし、名称・用途・行き先を一つのまとまりとして読む
- 同じリンクを一画面内で過剰に重複させない

## 検証

- Discord CTA の通常・hover・focus時のスタイル
- light / dark theme で文字が読めること
- Home から3つの実利機能へ到達できること
- チャンネル一覧に text / forum / voice / stage が存在すること
- FAQ、Rules、News に「準備中」や空状態が残らないこと
- 新規ページが静的エクスポートされること
- Unit、format、lint、typecheck、build、Playwright E2E
- `out/index.html` と `out/404.html` の生成

## 完了条件

- Home だけで、サイトに何があり何に使えるかを把握できる
- LayerNote、server bot、底力タイムに専用ページとHomeからの導線がある
- 音声・ステージを含む現行チャンネル構成が一覧に反映される
- 主要ページからプレースホルダー文言がなくなる
- Discord CTA が全配置で同じブランド表現になる
- GitHub Actions の Quality gate と E2E gate が成功する
